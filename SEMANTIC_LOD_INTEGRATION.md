# Semantic LOD Integration

This project can consume the PointNeXt + geometric postprocess CSV files generated by
`run_analyze_5_glbs.bat`. For a model named `c.glb`, the runtime looks for:

- `c_lod_constraints.csv` next to the model
- `lod_analysis_outputs/c_lod_constraints.csv` under the model folder
- `lod_analysis_outputs/c_lod_constraints.csv` under the project root

The CSV is loaded automatically during `Scene::init`. No command-line flag is required.

## Policy Inputs

The loader uses these CSV columns:

- `mesh_index` and `node_index` for mapping policies back to glTF parts
- `lod_priority` for the main P1-P5 simplification class
- `confidence` for low-confidence tracking
- `target_ratio_near`, `target_ratio_mid`, `target_ratio_far`
- `allow_cull`
- `screen_error_weight`

The PointNeXt class and the geometric size/shape/detail analysis should already be encoded
in these columns by the analysis script.

## P1-P5 Meaning

The policy is function-first, not size-first. A very large static object such as a
building shell, floor slab, foundation, housing, cover, or wall should simplify
quickly unless it is also a recognized motion, precision, or structural connector
part. Size alone does not imply preservation.

| Priority | Intended parts | Build policy | Runtime policy |
| --- | --- | --- | --- |
| P1 | micro parts, ambiguous small sheets, far-cullable tiny fasteners | most aggressive simplification | earliest coarse LOD / cull allowed |
| P2 | repeated fasteners, ordinary parts, large static bulk, foundations/housings/walls | aggressive simplification | early coarse LOD / cull allowed |
| P3 | visible but non-critical parts, high-detail large static bulk | balanced simplification | baseline LOD |
| P4 | controls, interfaces, moderate structural connectors, protected high-detail shapes | conservative simplification | later coarse LOD |
| P5 | motion/precision parts and truly key structural connectors | most conservative simplification | latest coarse LOD |

Current semantic intent:

- Fast simplify: screws, nuts, washers, pins, repeated small fasteners, large static plates, shells, covers, foundations, walls, simple blocks.
- Balanced: visible non-critical objects and very detailed static bulk that should not collapse too abruptly.
- Preserve: bearings, gears, pulleys, chains, motors, wheels, springs, rotating machinery, clamps, joints, brackets, and other load/connection-critical parts.
- Do not preserve merely because a mesh is large.

## Where It Affects LOD

Build-time:

- `clodConfig::simplify_ratio`
- `clodConfig::simplify_error_merge_previous`
- feature constraint thresholds and weights

Runtime:

- per-instance `RenderInstance::lodErrorScale`
- traversal shaders multiply the screen error threshold by this per-instance value

Important convention:

- larger `lodErrorScale` means coarser LOD is reached earlier
- smaller `lodErrorScale` means high detail is kept longer

## Rebuild Caches

After changing CSVs or this policy code, rebuild the model caches:

```bat
run_preprocess_semantic_lod_5_glbs.bat
```

If PointNeXt analysis already exists and only the P1-P5 policy logic changed, do
not rerun PointNeXt. Rebuild only the LOD constraint CSVs:

```bat
tools\pointnext_lod\run_rebuild_lod_constraints_only.bat
```

Then rebuild caches with `run_preprocess_semantic_lod_5_glbs.bat`.

For one model:

```bat
_bin\Release\t1.exe --scene _downloaded_resources\o1778.glb --processingonly 1 --processingpartial 1 --processingthreadpct 0.75
```

Then verify cache loading:

```bat
_bin\Release\t1.exe --scene _downloaded_resources\o1778.glb --cacheloadonly 1
```

## Visualize Policies

Use the UI `visualize` combo box and select `semantic lod policy`, or start from the command line:

```bat
_bin\Release\t1.exe --scene _downloaded_resources\o1778.glb --visualize 8
```

Color legend:

- P1: red, most aggressive simplification
- P2: orange, aggressive simplification
- P3: yellow, baseline policy
- P4: cyan, conservative policy
- P5: blue, most conservative policy
- grey: no semantic policy was loaded for that instance
